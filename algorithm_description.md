# Описание алгоритма поиска аномальных респондентов

## 1. Что считается аномалией

Аномалия — **чрезмерно высокая** дневная активность конкретного респондента по конкретному бренду.  
Малый OTS сам по себе **не является** аномалией. Все правила направлены исключительно на выбросы сверху (правый хвост распределения).

---

## 2. Шаги алгоритма

### Шаг 1: Фильтрация и агрегация

- Берём только строки с `BrandinDelivery = 1` и непустым `CategoryDelivery` (по условию колонка называется CategoryDelivery, но на предложенных данных название столбца CategoryNameDelivery. При этом в коде есть автодетект, позволяющий находить названия отличные от названия из условия).
- Для каждой тройки `(SubjectID, researchdate, BrandID)` вычисляем:

```
daily_ots = Weight × count_rows
```

где `count_rows` — количество строк данной тройки в отфильтрованном датасете, `Weight` — дневной вес респондента.

### Шаг 2. Обнаружение аномалий (внутри каждой группы date × BrandID × Category)

#### Критерий A — Robust Z-Score

rzscore = (daily_ots − median) / (1.4826 × MAD)

- **MAD** (медианное абсолютное отклонение) устойчив к выбросам.
- Коэффициент 1.4826 нормирует MAD для нормального распределения (аналог σ).
- Порог: **rzscore ≥ 3.5** — это хвост, встречающийся менее чем в 0.02% наблюдений нормального распределения.
- **Если MAD = 0** (все значения одинаковы): fallback на IQR-нормировку.
- **Защита от малых выборок**: для групп менее 5 наблюдений robust z-score не применяется — недостаточно данных для оценки разброса.

#### Критерий B — Доля в суммарном OTS бренда за день

share = daily_ots(i,j,k) / Σ daily_ots(*,j,k)

- Порог: **share ≥ 0.50** — один респондент занимает ≥ 50% суммарного OTS бренда за день.
- Экономически: если из репрезентативной панели один человек «генерирует» половину видимости бренда за день — это явная аномалия.
- Этот критерий работает даже для малых групп, где z-score ненадёжен.
#### Критерий C — Абсолютный перцентильный порог (внутри бренд-дня):
    Порог: daily_ots > Q75 + IQR_FACTOR × IQR  (Tukey fence)
    IQR_FACTOR = 3.0 (расширенный, чтобы не удалять норму)
    • Классический метод обнаружения выбросов Тьюки.
    • Направлен только вверх (нет нижней границы).
    • Применяется при группе ≥ MIN_GROUP_SIZE.

Аномалия фиксируется если ВЫПОЛНЕН ХОТЯ БЫ ОДИН критерий.

### Шаг 3: Формирование итогового списка удалений

- Если респондент признан аномальным хотя бы по одному бренду в день — пара `(SubjectID, researchdate)` добавляется в `anomalies.csv`.
- При пересчёте OTS удаляются **все** строки этого респондента за этот день (все бренды, все категории).

---

## 3. Почему выбранный подход разумен

| Свойство | Выполнение |
|---|---|
| Уровень брендов | Да — группировка по `(researchdate, BrandID)` |
| Численная причина | Да — `score`, `threshold`, `reason` для каждой аномалии |
| Порог из данных / статобоснован | Да — median/MAD из тех же данных; 3.5σ — общепринятый порог для выбросов |
| Только высокий OTS | Да — rzscore > 0 и share > 0 означают превышение нормы сверху |
| Малый OTS не аномалия | Да — критерии направлены на правый хвост |
| Защита от малых выборок | Да — `MIN_GROUP_SIZE = 5` |
| Детерминированность | Да — нет случайности, фиксированные пороги |
| Интерпретируемость | Да — `reason` объясняет каждую аномалию |
| Нет hardcode ID/дат | Да — все пороги статистические |

## 4. Параметры алгоритма

```python
RZSCORE_THRESHOLD = 3.5   # Robust z-score >= 3.5 => аномалия
SHARE_THRESHOLD   = 0.50  # Доля >= 50% => аномалия
MIN_GROUP_SIZE    = 5     # Минимум наблюдений для применения rzscore
```
